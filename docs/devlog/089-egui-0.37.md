# egui / eframe / egui_extras 0.33 → 0.37

**Status:** Complete (PR pending review)
**Branch:** `chore/egui-0.37`
**Date:** 2026-11-13 – 2026-11-14

## Why

- egui ≥ 0.35 shapes text with harfrust. That gives Arabic joining and Indic
  shaping (#108).
- epaint 0.37 rasterizes color glyphs itself (`color_fonts`: COLR, sbix,
  CBDT, EBDT). That replaces the swash path of our vendored epaint 0.33.3.
- eframe 0.37 disables the blocking swap on Wayland itself (egui#5136). That
  is the same fix as our `wayland_session` workaround (devlog 073).

## What changed

### Manifests
- egui/eframe/egui_extras 0.37.
- `rust-version` 1.95; the renderer's `rust-toolchain.toml` is pinned to
  1.95.0.
- eframe `clipboard` and `links` features: opt-in since 0.37. Without them
  copying and opening links silently stop working.
- epaint `color_fonts`.
- egui `experimental`, for the button theme (see Chrome size below).
- The `color-emoji` feature and its rewrite in
  `scripts/prepare-crates-manifest.py` are gone. crates.io builds now get
  color emoji from stock epaint.

### Vendored epaint
`crates/epaint` is stock epaint 0.37.0 plus one patch (`PATCH.md`, about 80
lines). 0.37 picks a cluster's face by its first char only, so:
- `❤️` (U+2764 U+FE0F) rendered monochrome;
- `🚀︎` (U+FE0E) rendered in color;
- ▶ ⚠ ✔ could be claimed by the color face.

The patch resolves emoji-presentation clusters (default emoji, U+FE0F)
against a face with color glyphs first, and everything else against one
without. It uses its own cache, so a bare `❤` does not inherit the color
answer. The tests in `src/system_fonts.rs` cover all three cases; with stock
behavior they go red.

### Renderer (`crates/egui_commonmark`)
- `ByteIndex` byte ranges; `source_id: impl Hash + Debug`.
- `scroll_area::State::offset` is private now; reads use
  `unclamped_offset()`.
- The #140 pre-selection clamp can no longer write the stored offset. A
  `ScrollableCache::pending_clamp` carries it into the next frame's
  `vertical_scroll_offset`.
- **ScrollArea id.** The state id is
  `ui.make_persistent_id(IdSalt::new(salt))`; `Id::new(x)` and
  `IdSalt::new(x)` hash differently. Getting it wrong loads `None`, and the
  clamp silently never fires.
- **Table row heights.** 0.37 rounds row heights to whole pixels.
  `body_line_height` returned 19.5 px for a row whose text laid out at 20 px,
  so the last line of tall cells was clipped. `body_line_height` now snaps to
  pixels the same way.
- `forward_shift_wheel_to_horizontal_scroll` was dead code in 0.33 already,
  and is removed:
  - egui converts Shift+wheel into a horizontal delta itself
    (`horizontal_scroll_modifier`), so the helper's vertical delta was always
    0;
  - `tests/shift_wheel_table.rs` pins both directions, and goes red if
    egui's conversion is switched off.
- Tests run through `tests/common/mod.rs`:
  - `run_frame` / `end_frame` clear `textures_delta`; 0.37 debug-asserts
    on an unconsumed delta;
  - `show_ctx` replaces `CentralPanel::show(ctx)`;
  - `store_offset` injects an offset through a serde round-trip, because
    `State` has no setter.
- The dense-table test was recalibrated to the pixel-snapped rows. The comment
  there records the arithmetic.

### App (`src/main.rs`, `src/system_fonts.rs`)
- `App::update(ctx)` → `App::ui(ui)`.
- `SidePanel`/`TopBottomPanel` → `egui::Panel` with `default_size` and
  `size_range`.
- `ctx.style_mut` → `global_style_mut`.
- `available_rect` is gone; the CentralPanel rect is kept in
  `document_rect` for the lightbox backdrop and the drop overlay.
- Removed `wayland_session` and the vsync option, now done upstream.
- Removed the scroll-while-selecting workaround: its API (`raw_scroll_delta`,
  writable `State::offset`) is gone, and 0.37 keeps the selection while
  wheel-scrolling on its own.
  - It also turned out to have doubled every wheel scroll on 0.33 (egui's
    scroll plus the re-applied delta). Removing it halved the per-click
    distance.
  - `line_scroll_speed` is set to 80 to keep what users know.
  - Measured with `scripts/scroll-regression.sh`: the walk reaches the
    bottom at frame 63, as on `main`.
- Edit mode's ratio-preserving offset is applied through
  `vertical_scroll_offset` (`Tab::pending_edit_offset`).
- **Chrome size.** 0.37's default button theme sizes button text from
  `TextStyle::Body` (`theme/default_style.rs`), not from `TextStyle::Button`.
  md-viewer sets `Body` to the document size, so menus, tabs, buttons and
  outline rows grew from 13 px to 16 px.
  - `ChromeButtonStyle` wraps `DefaultStyle` and swaps the font back to
    `TextStyle::Button`. It is registered with `replace_widget_theme`, which
    needs egui's `experimental` feature.
  - `button_padding` (8,2 → 4,1) and `interact_size.y` (20 → 18) are
    restored.
  - Screenshots against the 0.33 build now line up row for row.

## Verified (Xvfb)
- Arabic joined, RTL word order inside a run, Devanagari conjuncts, ZWJ
  family as one glyph.
- `❤` mono, `❤️` color, `🚀︎` mono; UI symbols mono.
- Selection survives wheel scrolling.
- Shift+wheel scrolls wide tables.
- Outline click lands the heading at the top.
- Find (menu → type → Enter) jumps to the match and highlights it.
- Clipboard and link crates are present in the build.
- `scroll-regression.sh` and `visual-regression.sh`: PASS.
